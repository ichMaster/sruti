# v1.1 — Issues

Issues for phase **v1.1 — Project skeleton and the receiver link** (version **v1 — The listening agent:
receiver link, CW decoder, pieces and sessions, piece explainer, the desktop app, session explainer**),
derived from the Tasks and DoD in [ROADMAP.md](../ROADMAP.md) §v1.1 and the contracts in
[ARCHITECTURE.md](../ARCHITECTURE.md). This file covers one phase; ids continue from the previous phase
(SRUTI-007 → **SRUTI-008…011**).

The phase writes the first product code: the Python project with its gates and CI, configuration, the
core event stream, and the receiver link. The link is sruti's own WebSocket client for one KiwiSDR audio
channel, built from the protocol the v0.1 spike observed. `kiwiclient` stays out of the product. The link
emits audio blocks, the signal level, link states and the raw messages; `sruti listen` runs it headless
and can record a session as WAV + capture. Characters arrive in v1.2.

**What needs to be done:**

  - Dev dependencies `ruff` and `pytest`, pinned in `uv.lock`.
  - Ruff configured in `pyproject.toml` with an explicit rule set, so the gate does not drift with
    ruff's defaults. `poc/` is linted too; `var/` is excluded.

  - Defaults live in code, and an optional `sruti.toml` overrides them. `sruti.toml` is gitignored;
    `sruti.example.toml` is committed.
  - v1.1 keys:
    - `receiver.host_port` (default the owner's Trémolat receiver);

    - `receiver.passband` (default `[300, 700]`);

- **The CLI shell** (`sruti/cli.py`): `sruti listen --receiver <host:port> --freq <kHz>` parses and

- **CI:** `.github/workflows/ci.yml` runs `uv sync`, `uv run ruff check .` and `uv run pytest` on push and

- **CLAUDE.md:** layout and commands updated to the real package paths.

event bus and the CLI parser tested.

**Acceptance criteria:**

### SRUTI-009 — The receiver protocol: messages, audio frames, the capture

**Description:**
The pure half of the receiver: the messages sruti sends, parsing what the receiver sends, unpacking SND
audio frames, sanitizing and writing the raw capture with its WAV. No I/O beyond the capture files.
Touches `src/sruti/receiver/{__init__,protocol,capture}.py` and `tests/`. Built from ARCHITECTURE §The
receiver and the v0.1 PoC (`poc/receiver/cw_spike.py`'s sanitizer, `poc/receiver/inventory.py`). No
`kiwiclient`.

**What needs to be done:**
- **Outgoing:** functions that build the documented messages, and nothing else:
  - `SET auth t=kiwi p=` and the greeting `SERVER DE CLIENT sruti SND`;
  - `SET ident_user=…`;
  - `SET mod=cw low_cut=… high_cut=… freq=…` (the signal's own frequency, 3 decimals);
  - `SET agc=…`, `SET compression=0`, `SET AR OK in=… out=44100`;
  - squelch off, `genattn` and `gen` off;
  - `SET keepalive`.
- **Incoming text:** parse `MSG name=value …`. Values are URL-decoded, and a bare name is a flag. Map the
  states:
  - `badp=1` → busy (all free channels taken);
  - `too_busy`, `down`, `redirect` → their states;
  - `audio_rate` and `sample_rate` → the audio format.

  Anything unknown is kept as a raw message, never fatal.
- **SND frames:** flags (1 byte), sequence (4, little-endian), S-meter (2, big-endian; dBm = 0.1 × value −
  127), then 16-bit big-endian samples. A compressed frame (flag `0x10`: the receiver ignored
  `compression=0`) is reported, not decoded. A truncated frame is dropped and counted.
- **The capture:**
  - The JSONL writer `{t, ws, dir, msg}` and the WAV writer (mono, 16-bit, the announced rate).
  - The sanitizer: `client_public_ip` masked anywhere in a `MSG`; `load_cfg`, `load_dxcfg` and
    `load_dxcomm_cfg` reduced to `omitted:<size>`; idempotent.
  - `SET keepalive` left out.

**Dependencies:** SRUTI-008

**Expected result:**
Every message in the v0.1 fixtures parses, every outgoing message is one of the documented ones, and a
capture written by sruti reads back the same.

**Acceptance criteria:**
- [ ] Every message type in `specification/examples/recordings/*.jsonl` parses, and the inventory (43
      types) matches ARCHITECTURE's table.
- [ ] SND frames unpack to the right sequence, dBm and samples, including a truncated and a compressed
      frame.
- [ ] The sanitizer masks the address in any position, keeps blob sizes on a second pass, and leaves
      everything else byte-identical.
- [ ] **Tests:** builders, the `MSG` parser and states, frame unpacking, sanitizer, capture round trip, and
      a test over the fixture captures.
- [ ] **Contract:** the receiver messages (CLAUDE.md §Contracts). A test pins the outgoing set to the
      documented one and the incoming inventory to ARCHITECTURE's table; the raw capture format is pinned
      by the round-trip test.
- [ ] **Gates:** lint, tests.

### SRUTI-010 — The receiver link: connect, stream, reconnect, and the fake receiver

**Description:**
The async link: it connects like the browser page, tunes, keeps the channel alive, and turns frames into
core events. It reconnects with backoff, and busy and time limit are states. The transport is injected,
so the fake receiver replays the v0.1 recordings in memory with no socket. Touches
`src/sruti/receiver/{link,backoff,transport,fake}.py` and `tests/`. Adds the `websockets` dependency.

**What needs to be done:**
- **Connecting:** `GET http://<host:port>/VER` for the timestamp `ts`, then
  `ws://<host:port>/ws/no_wf/<ts>/SND`. Send auth and the greeting, then the tuning messages; keepalive on
  the configured interval. One connection per run, identified as `sruti`.
- **Streaming:** each SND frame becomes an `AudioBlock` (timestamp, sequence, samples, rate) and a `Level`
  (dBm). Each text frame becomes a sanitized `RawMessage`, written to the capture when recording.
- **States** (`LinkState`): `connecting`, `listening`, `busy` (with the retry delay), `reconnecting`
  (attempt N), `time_limit`, `stopped`, `ended` (a replay finished).
- **Backoff** (`backoff.py`, pure): exponential from `reconnect_initial_s` to `reconnect_max_s`, with
  jitter from an injected random source. Busy waits at least `busy_retry_s`, so a full receiver is never
  hammered.
- **Time limit:** the time-limit state is entered on the receiver's time-limit signal. That signal is not
  yet observed: confirm its name from the KiwiSDR protocol, or from the live hour's capture in SRUTI-011.
  On it the link stops and does not reconnect by itself.
- **Transport:** a small interface (`connect`, `send`, `recv`, `close`), with the real one on `websockets`
  and `/VER` through `urllib` in a thread.
- **The fake receiver** (`fake.py`): it replays a WAV + capture pair as the receiver would. It sends the
  capture's `←` text messages in order and the WAV's samples as SND frames with sequence numbers. It can
  inject a drop, a `badp=1` and a delayed answer for tests. It runs in memory, so nothing listens.

**Dependencies:** SRUTI-009

**Expected result:**
Over the fake receiver, the link streams a v0.1 recording into the same audio and messages, survives a
drop, and waits politely on a busy receiver, all without a network.

**Acceptance criteria:**
- [ ] Replaying `cq.{wav,jsonl}` through the fake receiver yields audio blocks whose concatenated samples
      equal the WAV, and raw messages equal to the capture's received messages (sanitized).
- [ ] A drop mid-stream gives `reconnecting` (attempt 1) and then `listening`, with no lost or duplicated
      frames from the moment of the reconnect.
- [ ] `badp=1` gives `busy` with a delay ≥ `busy_retry_s`, and the next attempt waits for it (driven by an
      injected clock).
- [ ] The link sends only the documented messages (asserted on the fake transport's log).
- [ ] **Tests:** backoff (sequence, cap, jitter bounds), the state sequence for connect, drop, busy and
      stop, the replay equality, and the outgoing-message pin. No test opens a socket.
- [ ] **Gates:** lint, tests.

### SRUTI-011 — `sruti listen`: headless run, recording, and the live hour

**Description:**
`sruti listen` runs the link headless: it prints link states, the signal level every 10 s and,
optionally, the raw messages, and it records the session as WAV + capture. Then the DoD on a real
receiver: an hour on Trémolat that survives a dropped connection, and a replay of that recording through
the fake receiver. Touches `src/sruti/cli.py`, `src/sruti/listen.py` and `tests/`, plus ARCHITECTURE
(§Overview, §Core and the desktop app) for what headless prints in v1.1.

**What needs to be done:**
- **The command:**
  - `sruti listen --receiver <host:port> --freq <kHz>` with `--record <dir>` (WAV + capture, the v0.1
    format, named `<started>-<receiver>-<freq>`) and `--raw` (print every raw message).
  - Ctrl-C stops cleanly: state `stopped`, files closed.
  - A hidden `--drop-after <s>` closes the socket once, for the live reconnect check.
- **Output:** one line per state change, a level line every 10 s, and the frame and sample counters.
  Characters arrive in v1.2.
- **ARCHITECTURE fixes:**
  - The overview's directory edge is `http :80`, not `https :443`.
  - Headless mode prints link states and levels from v1.1, characters from v1.2.
- **The live hour** (owner-approved 2026-10-04; Claude runs it):
  - `sruti listen --receiver sdr.autreradioautreculture.com:8073 --freq <a CW frequency> --record
    var/recordings/ --drop-after 1200`, for an hour.
  - Wait for a free slot rather than retrying fast.
  - Hand the owner the log: states, reconnects, frame counts, gaps.
- **The replay check:** replay the hour's WAV + capture through the fake receiver and compare the audio and
  messages. This runs offline, from `var/recordings/`, which is not committed.

**Dependencies:** SRUTI-010

**Expected result:**
One command listens to a public receiver for an hour through a forced drop and leaves a recording that
replays to the same audio and messages.

**Acceptance criteria:**
- [ ] `sruti listen` prints states and levels and records WAV + capture in the v0.1 format; Ctrl-C leaves
      both files valid.
- [ ] **Tests:** the command over the fake receiver, covering states printed, files written, the drop and
      the reconnect, and a clean stop. A CLI test covers `--record` and `--raw`.
- [ ] **Contract:** the CLI gains `--record` and `--raw` (additive). ARCHITECTURE and the CLI test are
      updated together.
- [ ] **Gates:** lint, tests.
- [ ] **Manual (owner):** an hour of listening on Trémolat survives the forced drop. Confirmed from the
      run's log: one reconnect, audio flowing before and after, no crash.
- [ ] **Manual (owner):** the hour's recording replays through the fake receiver to the same audio and
      messages (the offline comparison's result).
