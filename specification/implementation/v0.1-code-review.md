## Findings

### 1. 🟠 Gap thresholds ignore the mark/gap bias — `cw_decode.py:204-210`

Thresholding the envelope in dB, midway between floor and peak, crosses the rising edge early and the
falling edge late. With the receiver's filter ringing on top, every mark comes out longer and every gap
shorter by a bias *b*. On `conversation` (E72U, ~28 WPM) marks measure 50–55 ms for dots and ~130 ms for
dashes, element gaps ~30 ms, so *b* ≈ 11 ms. The decoder sets its thresholds from the mark-based dot
(*dm* ≈ 52 ms). The character gap threshold is 2·*dm* = 104 ms, against a true character gap of
3*u*−*b* ≈ 115 ms. The word gap threshold is 5·*dm* = 260 ms, against ≈ 283 ms. Jitter pushes gaps under
both thresholds.

**Failure:** `5NN616`, `5NN485TRC`, `5NNE281` (words merged); `[err]` where two letters merge into an
unknown code. Synthetic CW passes at every speed because it has no bias.

**Fix:** also estimate the element gap *dg*, the lower cluster of recent gaps. Then *u* = (*dm*+*dg*)/2 and
*b* = (*dm*−*dg*)/2, and the thresholds become:
- dot or dash: 2*u*+*b*;
- character gap: 2*u*−*b*;
- word gap: 5*u*−*b*.

With no bias these reduce to today's 2·*dm* and 5·*dm*. **Regression:** the synthesizer gains a keying
bias (marks +15 ms, gaps −15 ms, as measured), with a self-test case at 28 WPM that fails today.

### 2. 🟠 `client_public_ip` masked only in first position — `cw_spike.py:101-102`

`sanitize()` masks the address only when the message *starts* with `MSG client_public_ip=`. Trémolat
sends it alone, but a receiver that bundles it (`MSG rx_chans=8 client_public_ip=…`) would write the
owner's address into a capture, and captures are committed to a public repository.

**Fix:** mask it inside the per-pair loop, wherever it appears. **Regression:** an offline `--selftest` for
the spike's sanitizer covers both positions and the configuration blobs.

### 3. 🟠 A steady carrier steals the tone search — `cw_decode.py:65-73`

The tone is the bin with the loudest 90th percentile. A dead carrier or a receiver spur is loudest at
every moment, so it wins. Its envelope has no contrast, so nothing decodes, even with CW elsewhere in the
passband. The passband mask (`typical >= max/100`) makes it worse: a carrier 20 dB over the noise drops
the noise bins themselves.

**Home:** v1.2, whose decoder follows the tone over time. Score bins by keying contrast (90th over 50th
percentile) as well as loudness, and take the passband reference from a median-filtered spectrum, so a
few carrier bins cannot set it.

### 4. 🟠 One tone per recording — `cw_decode.py:233-237`

The tone is chosen once for the whole file. In a contact the other station is often 50–100 Hz off. The
12 ms envelope window passes only about ±40 Hz, so the reply is weakened or lost: the answers in `cq`
(OK7DA/P) read worse than DJ0YI. **Home:** v1.2 (streaming, tone tracking, perhaps two tones at once).

### 5. 🟡 Empty band crashes `find_tone` — `cw_decode.py:71`

`--band 7000-8000` on 12 kHz audio, or a band narrower than one FFT bin, gives an empty mask, and
`typical[band].max()` raises `ValueError`. **Fix:** an empty band reports no tone, so the result is
"no CW found". **Regression:** a self-test case with a band above the Nyquist frequency.

### 6. 🟡 WPM reads low — `cw_decode.py:239`

The speed comes from the lengthened mark: the `cq` sender reads ~15 WPM, and synthetic 28 WPM reads
25.5. **Fix with #1:** report 1.2 / *u*.

### 7. 🟡 Scan steps carry the previous frequency — `cw_spike.py` `Sound._next_scan_step`

The WAV switches when `SET mod` is sent, but ~0.5–1 s of audio already on its way belongs to the previous
frequency. The 40 m analysis skipped the first second by hand. **Home:** v2 (finding traffic), which owns
scanning; drop audio for a second after a retune.

### 8. 🟡 `--replay` ignores the WAV — `cw_spike.py:60-90`

Replay still prints the receiver decoder's `cw_chars`, which audio captures do not have. **Home:** v1.1, whose fake
receiver replays the WAV + capture pair.

### 9. 🟡 `inventory.py` is lenient — `inventory.py:39-44`

A bare backticked name anywhere in a table row counts as documented, even in the description column.
Harmless today, since every observed type is listed explicitly. **Home:** backlog.

### 10. 🟡 High-duty signals hide themselves — `cw_decode.py:96-102`

Over a 4 s window the floor is the 25th percentile. A signal keyed down more than 75 % of the time (an
NCDXF beacon's four 1 s dashes) lifts the floor to its own level, so the contrast check reads no signal.
**Home:** v1.2 (gap-based floor, or a longer window when the floor jumps).

## What's solid

- **Listen only, by construction.** The spike sends the ten documented tuning messages and nothing else.
  The receiver decoder's messages exist only behind `--kiwi-decoder`, and a scan only repeats `SET mod`.
  There is one connection per run, named `sruti`.
- **"Never invent" holds.** An unknown code is `[err]` and noise alone decodes to nothing. The self-test
  checks both, including a tone search wider than the filter.
- **The decoder survived real audio.** Every miss in the 40 m scan was a weak station or a merged gap, and
  the call signs read right.
- **Privacy.** The owner's address is masked. The receiver's configuration blobs, which hold the
  receiver owner's email, are reduced to their size before captures are committed.
- **The inventory is checked by a script.** All 43 message types are in ARCHITECTURE's table.
