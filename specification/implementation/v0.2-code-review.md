## Findings

### 1. 🟠 A `(?)` excuses an invented call sign — `poc/eval_golden.py:101`

`invented_call_signs()` skips a call sign absent from the raw text when `(?)` follows it. Since SRUTI-007,
the prompt and `cw-hints.md` say the opposite: never offer a call sign that isn't in the text, not even as
an alternative with a question mark.

The exemption covers no legitimate case. A call sign joined from fragments (`IU3 F E J` → `IU3FEJ`) is
already found by the space-free comparison. What the exemption still lets through is a changed letter,
which is exactly the "correction" the never-invent rule forbids.

**Failure:** an answer saying `UW3WU (?) UR3WU (?)` passes, and `UR3WU` is invented. None of the saved
runs relied on the exemption (checked), so removing it changes no recorded result.

**Fix:** drop the exemption. **Regression:** a self-test case where an invented call sign marked `(?)`
must fail.

### 2. 🟡 `--rescore` trusts the pieces — `poc/eval_golden.py:181-194`

Rescoring reads the golden file as it is now and checks each saved answer against `pieces[i]`. If a piece
was re-cut after the run, the answer is scored against text the model never saw. Coverage and call-sign
checks then give a wrong verdict, silently.

**Fix:** compare the saved `piece` with the current one, and refuse with a clear message on a mismatch.
**Regression:** a self-test case that rescores a run whose piece differs and expects the refusal.

### 3. 🟡 Unreadable-text check is token-exact — `poc/eval_golden.py:107-119`

The check finds the model's meaning only for a token identical to the reference token, spaces ignored. A
model that splits `G T EIM [err]` into `G`, `T`, `EIM [err]` and reads them as words escapes it. **Home:**
v1.4, whose explainer tests own the measured checks; align tokens by position there.

### 4. 🟡 Coverage is lenient — `poc/eval_golden.py:87-90`

A raw token counts as covered if it is a substring of the joined gloss tokens. One-letter fragments (`E`,
`I`, `T`) are therefore always covered. **Home:** v1.4 (an ordered alignment of raw tokens to gloss
tokens).

### 5. 🟡 2026 prices hard-coded — `poc/eval_golden.py:33`

`PRICE_IN, PRICE_OUT = 0.75, 3.75` holds through 2026-12-31, and the prices double on 2027-01-01. **Home:**
v1.4, where the cost accounting lives in the core and the prices in configuration.

### 6. 🟡 A blocked answer raises — `poc/explain_piece.py:178`

`out["candidates"][0]["content"]["parts"][0]["text"]` raises `KeyError` or `IndexError` when Gemini
blocks or returns nothing. The eval records it as a failed call, which is right for a PoC. **Home:** v1.4,
where the rule is "raw text only for that piece, never a crash".

### 7. 🟡 Session-tier glossary stated, not measured — ARCHITECTURE §The two tiers

The table now names `glossary/cw.md` as the session tier's input. That is what `poc/explain_session.py`
uses, but no eval compared forms for the session tier. **Home:** v1.6, which should measure it the way
v0.2 measured the piece tier.

## What's solid

- **Paid calls are opt-in by construction.** No `--live`, no call; the self-test is offline; `--rescore`
  re-checks saved answers without spending. The Gemini key travels only in the `x-goog-api-key` header,
  and the Anthropic key only into the SDK client. Neither appears in a report (checked).
- **The three actions follow the spec.** `none` bumps a counter, `append` adds one entry, `rebuild`
  replaces exactly the shown window. A schema-broken answer leaves section 3 untouched.
- **The checks are calibrated.** The references pass them 15/15, and each false alarm the live runs
  surfaced became a self-test case.
- **The eval caught a reference error.** 002's `5 5N` is 559, not 599. The human-written bar was wrong,
  and the tool showed it.
