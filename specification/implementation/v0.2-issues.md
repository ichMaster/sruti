audio, the piece model proven**), derived from the Tasks and DoD in [ROADMAP.md](../ROADMAP.md) §v0.2 and

builds an opt-in eval that runs `gemini-3.8-flash` over them, and settles the piece prompt and the glossary

It builds on the PoC (`poc/explain_piece.py`, `poc/RESULTS.md`) and the v0.1 fixtures. The piece explainer
module itself is v1.4.

## v0.2 — Prove the piece model

### SRUTI-005 — Golden examples with reference answers

**Description:**
Make example 001 and the v0.1 recordings `cq` and `conversation` into golden examples. Each gets the decoded
text cut into pieces, a reference gloss and message for every piece (the piece tier's bar), and a reference
Ukrainian explanation of the whole session (the session tier's bar). Touches
`specification/examples/001-italian-ragchew.md`, the new `002-…` and `003-…` files, and a small session-tier
script, `poc/explain_session.py`.

**What needs to be done:**
- **One format for every golden example**, one Markdown file each:
  - Source (receiver, frequency, date, recording).
  - `## Pieces`: one fenced block per piece, in order, exactly the decoder's text.
  - `## Reference — piece tier`: per piece, the gloss (token → meaning, every token) and the section-3
    message with its action.
  - `## Reference — session tier`: the Ukrainian explanation.
  - What the decoder got wrong, the ambiguity a good answer keeps open, and the bar.

  The eval (SRUTI-006) reads `## Pieces` and the references, so the headings are fixed.
- **001:** keep the existing reference explanation; add the per-piece reference gloss and message for its
  three pieces.
- **002 (`cq`, DJ0YI calling CQ POTA, OK7DA/P answering)** and **003 (`conversation`, E72U's TRC DX
  Contest run, nine contacts):**
  - The raw text is the prototype decoder's output recorded in
    `specification/examples/recordings/README.md`, after the v0.1 review.
  - Cut it by the piece rules of ARCHITECTURE §Pieces and sessions: an end-of-turn prosign standing alone,
    or 200 characters. The pause cut needs timestamps the prototype does not give, so note where a pause
    would likely have cut.
  - Write the reference gloss and message per piece. In 003 the serials are cut numbers (`T56` = 056), and
    the repeated `TU E72U` / `TEST E72U` calls carry no new content: the right action is `none` or a short
    append.
- **The reference Ukrainian explanations:** `poc/explain_session.py` sends the glossary and the whole
  session to Claude Opus 5.5 and prints the Ukrainian explanation, in example 001's reference style. It
  uses the official `anthropic` SDK, run with `uv run --with anthropic`. The key comes from `.env` and
  never goes into argv, a log or a URL. Run it for 002 and 003 (owner-approved, ≈ $0.03 each), then edit
  the result into each file as its reference after the owner's review.

**Dependencies:** None

**Expected result:**
Three golden examples in one format, each with a reference gloss and message per piece and a reference
Ukrainian explanation, approved by the owner.

**Acceptance criteria:**
- [ ] `001`, `002` and `003` follow the one format; each piece's raw text matches the decoder output it
      came from.
- [ ] Every piece has a reference gloss covering every token, and a reference message with its action.
- [ ] Every example has a reference Ukrainian explanation; call signs, Q-codes and quoted original text
      stay as sent, and unreadable text is `[...]`.
- [ ] `poc/explain_session.py` reads the key from `.env` only; `ruff check poc` is clean.
- [ ] **Tests:** none automated (no test suite before v1.1). The eval's parser (SRUTI-006) reads all three
      files.
- [ ] **Gates:** n/a — no `pyproject.toml` before v1.1.
- [ ] **Manual (owner):** the reference answers of 002 and 003 are approved as the bar.

### SRUTI-006 — The golden-example eval script

**Description:**
`poc/eval_golden.py` runs the piece explainer over every golden example, piece by piece, carrying the
section-3 state exactly as the agent will. It checks what can be checked automatically, and writes a
side-by-side report of the model's answers against the references for the owner to judge. It reuses the
prompt and the Gemini call of `poc/explain_piece.py`, so there is one prompt to settle.

**What needs to be done:**
- **Inputs:** the golden examples under `specification/examples/` (the format of SRUTI-005), `--model`
  (default `gemini-3.8-flash`), `--glossary full|hints|none`, `--examples` to pick a subset.
- **The run:** for each example, feed its pieces in order with the last 5 raw pieces and the recent
  section-3 entries. Apply `none` / `append` / `rebuild` to section 3 as ARCHITECTURE §The four sections
  says; `rebuild` replaces only the window the model was shown.
- **Automatic checks per piece:**
  - the answer validates against `{gloss, action, message/rebuilt}`;
  - latency ≤ 5 s;
  - the gloss covers every raw token;
  - no call sign appears in the message or gloss that is not in the raw pieces, unless marked `(?)`;
  - an unreadable stretch is `[...]`, not a guess;
  - the share of `rebuild` actions.
- **Cost:** tokens and dollars per piece from the response's usage, at ARCHITECTURE's prices.
- **The report:** one Markdown file per run under `poc/eval/`, named
  `<date>-<model>-<glossary>.md`. It holds the checks, the latency and cost totals, and per piece the raw
  text, the model's gloss and message beside the reference.
- **Offline self-test:** `--selftest` drives the whole loop with canned model answers. One canned answer is
  good, one invents a call sign, one breaks the schema, and one rebuilds. It must flag exactly the bad
  ones, with no network.
- **Opt-in only:** a real run needs `--live`; without it the script refuses to call the API. The Gemini key
  travels in the `x-goog-api-key` header only.

**Dependencies:** None

**Expected result:**
One command runs a model over all golden examples and produces a report with automatic checks, latency
and cost; the same loop is tested offline.

**Acceptance criteria:**
- [ ] `eval_golden.py --selftest` passes offline and flags exactly the invented call sign, the broken
      schema and nothing else as failures. The rebuild is counted, not failed.
- [ ] Without `--live` the script makes no network call.
- [ ] The report lists, per example and per piece: the checks, latency, tokens, cost, and the model's
      gloss and message beside the reference.
- [ ] The key is read from `.env` and sent only in the `x-goog-api-key` header; it appears in no output.
- [ ] **Tests:** the offline self-test with canned answers (no test suite before v1.1).
- [ ] **Gates:** n/a — no `pyproject.toml` before v1.1; `ruff check poc` clean.

### SRUTI-007 — The run: settle the piece prompt and the glossary form

**Description:**
Run the eval live with both glossary forms, compare them on the golden examples against the bar, fix the
prompt and the glossary where the runs miss, and write the settled prompt and glossary form into
ARCHITECTURE. The results go into `poc/RESULTS.md`.

**What needs to be done:**
- **Baseline:** `eval_golden.py --live --glossary hints` and `--glossary full` over 001–003 (owner-approved
  real calls, ≈ $0.2–0.5 in all).
- **Fix what misses:**
  - The new examples bring traffic the PoC never saw: contest exchanges (`TEST`, `TU`, serials in cut
    numbers), POTA (`CQ POTA`, `/P`), `AGN`, `NR?`, `CALL?`.
  - Add the conventions models get wrong to `glossary/cw-hints.md`, and the plain expansions to
    `glossary/cw.md`.
  - Adjust the prompt in `poc/explain_piece.py`, for example the PoC's finding that "expand only against
    the glossary" was too strict.
  - Re-run until the runs stop improving.
- **Decide:** the glossary form (full or hints) and the final prompt, on quality first, then latency and
  cost.
- **Write it down:**
  - ARCHITECTURE §The two tiers gets the piece prompt (system instructions, the user-message layout, the
    schema) and the glossary form.
  - The token and cost estimate in §The two tiers is updated to the measured figures.
  - `poc/RESULTS.md` gets a v0.2 section: the runs, the checks, latency and cost per piece, the decision.
- **`rebuild`:** report how often the model chose it and whether each was justified (ARCHITECTURE §The
  four sections asks v0.2 to measure this).

**Dependencies:** SRUTI-005, SRUTI-006

**Expected result:**
A measured decision on the glossary form and the prompt, written into ARCHITECTURE, with the eval reports
that back it.

**Acceptance criteria:**
- [ ] Eval reports for both glossary forms over all three golden examples are committed under `poc/eval/`.
- [ ] Every piece of the chosen configuration passes the automatic checks; latency ≤ 5 s per piece (warm).
- [ ] ARCHITECTURE §The two tiers holds the piece prompt, the glossary form and the measured token and cost
      figures; `poc/RESULTS.md` holds the v0.2 results and the decision.
- [ ] **Contract:** the piece explainer schema `{gloss, action, message/rebuilt}` is unchanged (or, if the
      run shows it must change, ARCHITECTURE is updated with it and the change is flagged for v1.4's
      pinning test).
- [ ] **Gates:** n/a — no `pyproject.toml` before v1.1; `ruff check poc` clean.
- [ ] **Manual (owner):** on the golden examples the model reaches the bar — the substance of each
      reference message, every abbreviation explained, call signs exact, unreadable text marked.
- [ ] **Manual (owner):** the glossary form and the prompt are accepted.
