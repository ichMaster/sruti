## v0.1 — Text from the receiver

### SRUTI-001 — kiwiclient license and the CW spike with raw capture

**Description:**
Check `kiwiclient`'s license before anything depends on it, then write the spike the owner runs against a
public receiver: `poc/receiver/cw_spike.py`. It opens one CW audio channel through `kiwiclient`, attaches
the `CW_decoder` extension, prints the decoded text live and writes every raw extension message to a JSONL
capture; a replay mode prints a saved capture's text without connecting.

**What needs to be done:**
- **License:** read the license of [jks-prv/kiwiclient](https://github.com/jks-prv/kiwiclient) and record
  its name and the pinned commit. If there is none, or it does not allow use from this MIT project, stop and
  raise it with the owner (the alternative is a minimal WebSocket client written from the protocol table in
  ARCHITECTURE §The receiver).
- **The checkout:** `kiwiclient` lives outside the tracked tree, in `var/kiwiclient/` (gitignored), pinned to
  the recorded commit; the spike's docstring says how to get it.
- **The spike** `poc/receiver/cw_spike.py`, standard library plus `kiwiclient`:
  - arguments `--receiver host:port`, `--freq <kHz>` (passband centre, `--pbc`), `--pboff <Hz>` (default
    500), `--out <file.jsonl>`, `--replay <file.jsonl>`;
  - one connection, identified as `sruti`; sends only the documented `SET` messages — `ext_switch_to_client`,
    `cw_pboff`, `cw_wpm` (0 = auto), `cw_start` — and `cw_stop` on exit; nothing else, ever;
  - prints the URI-decoded `cw_chars` as they arrive, plus `cw_wpm` and `cw_train` on a status line;
  - writes every message in both directions to the capture, one line each;
  - reports "receiver busy" and "time limit reached" and exits cleanly; Ctrl-C disconnects;
  - `--replay` prints the text of a saved capture and never connects.
- **The raw-capture format** — one JSON object per line, `{t, dir, msg}` (`t` epoch seconds, `dir` `"→"`
  sent / `"←"` received, `msg` the message exactly as on the wire) — documented in ARCHITECTURE
  §The receiver. It is what v1.1's fake receiver replays.

**Dependencies:** None

**Expected result:**
The owner can run one command against a public KiwiSDR and get live decoded text and a replayable JSONL
capture, with the license question settled first.

**Acceptance criteria:**
- [ ] The license name and the pinned commit are recorded in the execution report, or the owner has chosen
      the alternative.
- [ ] Reading the code shows only the documented `SET` messages are sent, over one connection named `sruti`.
- [ ] `--replay` on a hand-made capture built from the ARCHITECTURE protocol table prints the expected
      text, `[err]` included, offline.
- [ ] **Tests:** none automated (ROADMAP §v0.1: a spike); the offline replay check above stands in.
- [ ] **Contract:** the raw-capture format `{t, dir, msg}` is added to ARCHITECTURE §The receiver; the test
      that pins it lands with v1.1's fake receiver.
- [ ] **Gates:** n/a — there is no `pyproject.toml` before v1.1 (CLAUDE.md §Acceptance gates).

### SRUTI-002 — Live sessions: receivers, tone offset, three recordings

**Description:**
The owner runs the spike against public receivers: picks three, finds the `cw_pboff` at which the decoder
hears a 14.100 MHz beacon, and records three sessions. Claude checks the recordings offline with
`--replay` and commits them as fixtures under `specification/examples/recordings/`.

**What needs to be done:**
- **Owner — receivers:** pick three public receivers from `kiwisdr.com/public` with good reception on 7 and
  14 MHz and free slots; note `host:port` and location for each.
- **Owner — the tone offset:** on 14.100 MHz with the frequency as passband centre, find the `--pboff` at
  which the beacon call signs decode (start at 500 Hz; the earlier observation was a ~1003 Hz tone). Note
  the working value and what explains the earlier ~1003 Hz.
- **Owner — three recordings** with `--out`:
  - `beacons.jsonl` — 14.100 MHz, at least one full 3-minute NCDXF cycle;
  - `cq.jsonl` — a CQ run;
  - `conversation.jsonl` — a conversation in 7.000–7.040 or 14.000–14.070 MHz, several minutes.
- **Owner:** hand the recordings and notes over (drop them in `var/recordings/` or send them).
- **Claude, offline:** `--replay` each recording; check the beacon recording contains known beacon call
  signs (e.g. `OH2B`); commit the three files and a short `specification/examples/recordings/README.md`
  (receiver, frequency, date, `cw_pboff`, what each recording contains).

**Dependencies:** SRUTI-001

**Expected result:**
Three replayable recordings of real decoder output are in the repository, with the receivers and the
working `cw_pboff` written down.

**Acceptance criteria:**
- [ ] `--replay` of each recording prints readable text offline; the beacon recording contains at least one
      known beacon call sign.
- [ ] The recordings and their README are committed under `specification/examples/recordings/`.
- [ ] **Gates:** n/a — no code changes.
- [ ] **Manual (owner):** on 14.100 MHz the beacon call signs (e.g. `OH2B`) appear as text.
- [ ] **Manual (owner):** a live conversation in 7.000–7.040 or 14.000–14.070 MHz produces readable text.
- [ ] **Manual (owner):** the three recordings are saved and handed over, with the receivers and the
      working `cw_pboff`.
