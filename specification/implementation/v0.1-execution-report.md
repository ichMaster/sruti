### SRUTI-001: kiwiclient license and the CW spike with raw capture
**Status:** completed · **Commit:** 1463e93 · **GitHub:** #1 (closed)
**Gates:** [ ] lint (n/a, no `pyproject.toml` before v1.1) · [ ] tests (n/a; the spike has none per ROADMAP §v0.1)

- **License:** jks-prv/kiwiclient at `4eb733e6b6147f7fbeb97ced64cdac029b202d18` has no license — no file, no
  statement in the README or the code; only the vendored `mod_pywebsocket` carries Google's BSD terms.
  The owner chose: kiwiclient serves only the v0.1 spike from an uncommitted checkout in `var/kiwiclient/`,
  and the v1.1 `receiver` module is sruti's own client. ARCHITECTURE, ROADMAP v1.1, CLAUDE.md and the
  execute skills were updated in the same commit.
- **Spike:** `poc/receiver/cw_spike.py` opens the SND channel (CW, 300–700 Hz, the frequency as passband
  centre, so the carrier is 0.5 kHz below it) and the `CW_decoder` on the EXT socket, tied by a shared
  timestamp; prints the decoded text; writes the capture; `--replay` prints a capture's text and message
  types offline.
- **Drift from the issue text:** the issue said only the decoder `SET` messages would be sent. The SND
  channel cannot exist without its tuning messages (`auth`, `ident_user`, `mod`, `agc`, `AR OK`,
  `squelch`/`gen` off, `keepalive`). They are the "documented tuning messages" CLAUDE.md allows; they were
  undocumented, so ARCHITECTURE §The receiver now lists them. The capture format gained a `ws` field
  (`SND` / `EXT`) so the fake receiver knows which socket a message used.
- **Checks:** `--replay` of a hand-made capture printed `CQ CQ DE OH2B MAESTRO [err]L INO K` and skipped a
  corrupt line; both kiwiclient streams driven through a fake socket sent exactly the documented messages;
  `ruff check` on the spike passes. Not yet run against a live receiver — that is SRUTI-002.
