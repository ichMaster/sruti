## Findings

### 1. 🟠 A silent stall hangs the link — `src/sruti/receiver/link.py:120-128`

`_session` awaits `transport.recv()` with no timeout. Several things end a connection without a TCP close:
- the Mac sleeps and wakes;
- the network changes;
- a NAT drops the mapping;
- the receiver's process hangs.

WebSocket pings are off (`ping_interval=None`), and the keepalive writes into the local socket buffer.
So nothing notices for many minutes, until TCP's retransmission timeout.

**Failure:** the laptop sleeps for two minutes mid-session. On wake the link still says `listening`, no
`AudioBlock` arrives, and no reconnect happens. The live hour's forced drop was a clean close, so it
could not show this.

**Fix:** a silence watchdog. A healthy channel sends ~23 frames a second, so no data for `silence_s`
(configuration, default 20 s) means the connection is dead. The link closes it, and the normal reconnect
path takes over. **Regression:** a fake transport that stalls after N frames; the link must report
`reconnecting` and resume on the next connection.

### 2. 🟡 Unbounded message size — `src/sruti/receiver/transport.py` (`max_size=None`)

The largest message a receiver sent was ~47 KB (`load_dxcfg`); audio frames are ~1 KB. `max_size=None`
lets a misbehaving receiver push arbitrarily large frames into memory.

**Fix:** cap at 1 MiB. **Regression:** a unit test that captures the arguments `connect_kiwisdr` passes
to `websockets.connect`: max size, no pings, no compression, the `/ws/no_wf/<ts>/SND` path. `/VER` is
stubbed, so no network.

### 3. 🟡 `redirect` and `down` — `src/sruti/receiver/link.py` (the refusal path)

Both become `busy` with backoff on the same host. That is polite, and right for v1. Following a
redirect, or choosing another receiver, belongs to receiver selection. **Home:** v2, finding traffic.

### 4. 🟡 Config read from the current directory — `src/sruti/config.py:load_config`

Running `sruti listen` outside the repo ignores its `sruti.toml` and `.env`. sruti runs from the repo
(CLAUDE.md), so this is harmless now. **Home:** v1.5, where the config panel writes the file and a fixed
location must be chosen.

### 5. 🟡 Unbounded queues — `src/sruti/events.py:Bus`

The only subscriber today, the terminal printer, keeps up easily. The store and the segmenter (v1.3) and
the explainers (v1.4) will subscribe too. **Home:** v1.3: decide on a bounded queue and what to drop
(never characters).

### 6. 🟡 Time-limit names unconfirmed — `src/sruti/receiver/link.py:TIME_LIMIT_SIGNALS`

The live hour did not reach Trémolat's 600-minute inactivity limit. **Home:** backlog: confirm when a
receiver first sends it, and record it in ARCHITECTURE's message table.

### 7. 🟡 Ctrl-C at the edges — `src/sruti/listen.py`

The handler covers the whole run except the first and last milliseconds. **Home:** cleanup.

## What's solid

- **Listen only, enforced twice.** The builders are the only way to send, and tests pin both the
  builder set and the fake receiver's log to ARCHITECTURE's table. The live hour sent exactly the
  documented messages, once per connection.
- **A polite guest.** One connection at a time; busy waits at least 30 s; the backoff is jittered; a
  refusal closes the socket.
- **Recordings that replay.** The hour's 43 M samples and 475 messages replay byte-identical. Python's
  `wave` patches the header after every write, so even a crash leaves a readable WAV.
- **No secrets in the receiver path.** Config exposes the keys only as `set` or `missing`, tested.
- **Tests never open a socket.** The fake receiver runs in memory through the injected transport.
